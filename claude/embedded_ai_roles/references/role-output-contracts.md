# Role Output Contracts

这个文件统一约束 10 个角色的输出结构和最小质量门槛。

## 通用输出骨架

角色输出尽量采用以下骨架：

```markdown
## 目标
## 已确认事实
## 分析与判断
## 风险与待确认
## 建议动作 / 交付物
```

## 证据表达规则

- `已确认事实` 中只放有证据支撑的内容
- `风险与待确认` 中放尚未验证的内容
- 如果是推断，明确写成“推断”或“建议”

## 交付物命名建议

- 规划类：`方案.md`、`Todo.md`
- 调试类：`debug.json`
- 结构类：`topStruct.md`
- 路由类：`task-packet.json`
- 测试类：`测试报告.md`
- 发布类：`交接清单.md`

## 角色差异化重点

- 产品经理：目标、范围、优先级、验收
- 架构师：边界、分层、接口、权衡
- 硬件：约束、接口、电气风险
- BSP / 驱动：底层链路、版本、可支持性
- 系统 / 应用：进程模型、接口契约、容错
- 测试：覆盖、门禁、验证方法
- DevOps：可构建性、可复现性、流水线门禁
- 项目经理：里程碑、依赖、风险、决策追踪

## 最小质量门槛

1. 不遗漏风险与待确认项
2. 不把假设伪装成事实
3. 给出可执行的下一步，而不是停留在抽象建议
4. 尽量减少“平台固定值”的硬编码
5. 输出应能回填到 `task-packet.json` 的交接字段，而不是只给大段散文
6. 如果涉及模型路由，必须明确写清它是否启用，以及由谁显式启用

## 多角色交接最低字段

当角色输出要被汇总、拼接或交接时，至少应能映射到以下字段：

- `目标与范围`
- `关键证据`
- `当前判断`
- `待确认与阻塞`
- `建议下一步`
