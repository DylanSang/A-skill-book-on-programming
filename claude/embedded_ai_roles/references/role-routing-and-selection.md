# Role Routing And Selection

这个文件告诉工作流应该如何选择最少必要角色，减少把 10 个角色全部加载进上下文的开销。

## 默认最小集合

### 新功能规划

- 产品经理
- 系统架构师
- 测试工程师
- 项目经理

### 硬件相关变更

在默认最小集合上加：

- 硬件工程师

### 内核 / 设备树 / BSP / 驱动相关

在默认最小集合上加：

- BSP 工程师
- 驱动工程师
- 系统工程师

### 用户空间服务 / 应用 / AI 逻辑

在默认最小集合上加：

- 系统工程师
- 应用工程师

### 编译 / 部署 / CI / 构建故障

在默认最小集合上加：

- DevOps 工程师
- 测试工程师

## Debug 模式的常见组合

- 编译失败：系统工程师 + 应用工程师 + DevOps + 测试
- DTS / 驱动不生效：硬件工程师 + BSP + 驱动 + 测试
- 运行时逻辑异常：系统工程师 + 应用工程师 + 测试
- 发布阻塞：DevOps + 项目经理 + 测试

## 选择原则

1. 先用最少角色覆盖任务
2. 缺少关键证据或跨层冲突时再扩展角色集合
3. 如果角色观点重复，把共享规则迁回 references，而不是继续扩充角色正文
